# 知行·数学建模实验室

统一的高中数学建模网页。上传教学计划与学习进度，选择主题和探索方式，由AI设计递进题目、交互场景与计算规则。页面根据返回的结构化项目实时渲染，学生的操作状态随提示请求一并发送给模型。

## 启动

需要Node.js22或更高版本，使用内置模块，无需安装依赖。

```powershell
node src/server.mjs
```

打开[本地demo](http://127.0.0.1:3000)。可用PORT环境变量更换端口。

```powershell
node --test src/tests/*.test.mjs
```

## 使用流程

１．选择服务商，输入模型名称和API密钥。连接会实际调用一次模型，成功后显示连接状态。

２．上传或填写教学计划与进度，选择数学模块、兴趣和活动时长。探索方式可选几何、优化、概率、路线，也可以交给AI搭配。

３．点击“生成建模项目”。已连接时会调用AI生成新题目，生成结果标明实际模型、时间、耗时和请求编号。每个新项目包含至少两种交互实验，题目、场景配置与规则由本次模型响应确定。

４．在工作台拖动图形、分配资源、抽样或选择路径，记录自己的判断。同一个实验被后续任务引用时，保留此前的操作结果。

５．填写尝试或具体困难后请求提示，AI会收到当前场景、所有实验状态和既有作答。已连接AI时，预置示例同样可以使用实时提示与反馈。

６．记录阶段成果并导出JSON，保留项目、生成来源、作答、提示与实验快照。

教学计划和进度支持UTF－8编码的TXT、MD、Markdown、TeX和CSV文件。计划上限３万字，进度上限４０００字；较长的进度文件需要在页面内整理。学习记录自动保存在当前浏览器，密钥不会进入本地存储或导出文件。

## 知识图谱

点击顶部“知识图谱”，或打开[知识图谱页面](http://127.0.0.1:3000/knowledge-graph.html)，可以浏览五册教材的知识依赖。页面直接读取books目录中的knowledge-graph.full.json，包含２３４个知识点和４１８条依赖边。

支持按教材筛选、按名称或章节搜索、按编号定位，以及缩放和平移。选中节点后显示学习要求、教材页码、原文定位片段和直接前置、后续知识。勾选“只看当前节点的直接依赖”可查看包含跨册知识的局部图；点击前置或后续知识可以继续浏览。

图谱可在进入建模项目前浏览。前置依赖为教材内容分析结果，完整JSON中的validation记录了有向环检查结果。修改服务端代码后，需要重新启动本地服务；更新图谱JSON后，刷新页面即可读取新内容。

## 根据模型设计渲染实验

| 实验类型 | 直观操作 | 由AI设计的内容 |
| --- | --- | --- |
| 几何探索 | 拖动点、改变长度和角度、观察图形与约束、保存对照 | 点、线段、矩形、多边形、圆和椭圆；参数范围；指标公式与约束 |
| 方案优化 | 调整各类数量、查看资源占用、比较可行方案 | 决策选项、目标贡献、资源消耗和容量 |
| 概率模拟 | 调整总体、放回规则和抽取数量，运行随机试验 | 对象类别、数量、目标事件和试验规模 |
| 路线规划 | 点击相邻节点、比较路径、检验到达条件和代价 | 地图节点、连接关系、权重、起终点与可选必经点 |

新项目采用version为２的协议。experiments数组描述实验，stages数组通过interaction.experimentId引用实验。同一任务情境可先探索几何，再做资源分配，或把随机模拟与路线选择结合起来。界面会保持每个实验各自的状态；跨实验的知识联系和成果引用由任务与作答呈现。

几何计算使用受限的数学表达式解析器，支持四则运算、乘方、三角函数等数学操作。模型输出被解释为图形和规则数据。新增可视组件需要同时更新渲染器、协议校验与集中提示词。

## 题目多样性与API作用

旧版协议强制所有题目使用训练数据、验证数据、模型参数与误差比较。新版协议已经移除这些生成要求，自动推荐近期使用较少的实验类型，并将最近项目交给模型作为避免重复的参考。用户指定探索方式时，该类型必须出现在生成结果中。

生成、提示和反馈接口返回调用来源信息。页面分别显示“AI已连接”和“题目来源”，避免把旧示例误认为新生成内容。生成失败时显示错误，不把预置项目替换为AI结果。

API支持OpenAI、DeepSeek、通义千问及自定义OpenAI兼容Chat Completions接口。DeepSeek默认使用deepseek-flash，模型名称可编辑。密钥仅保存在本地后端会话内存，默认２小时失效，断开或重启后清除。教学资料、生成项目及解题状态会发送到用户选择的服务商。

## 示例与旧项目

默认示例“规划一次火星观测”包含轨道几何、观测资源分配和天气概率试验。地球用单位圆近似，火星采用a＝１．５２４AU、e＝０．０９３４的近似椭圆。角度用于比较几何位置，不对应实际日期。资源价值和天气比例是教学设定。

轨道参数参考[JPL近似行星位置说明](https://ssd.jpl.nasa.gov/planets/approx_pos.html)。若要研究真实日期与位置，可根据[JPL Horizons官方说明](https://ssd.jpl.nasa.gov/horizons/manual.html)获取计算历表。

原来的火星轨道拟合示例保留在demo-orbit-fitting.json。已保存的version为１项目仍可打开和操作；新生成项目使用多场景协议。

## 文件组织

所有源码与提示词位于src目录。

| 文件 | 作用 |
| --- | --- |
| server.mjs | API代理、会话与调用来源记录 |
| prompts.json | 连接、生成、修复、提示、反馈和实验协议的全部提示词 |
| lib/project-schema.mjs | 新旧项目协议、表达式与场景约束校验 |
| public/app.js、views.js、styles.css | 页面流程、学习记录和界面 |
| public/experiment-workbench.js | 根据实验类型选择渲染器并保持各实验状态 |
| public/expression.js | 安全的数学表达式解析与计算 |
| public/scenes | 几何、优化、概率、路线渲染器与样式 |
| public/lab.js、lab.css | 旧版拟合项目兼容渲染 |
| demo-project.json | 天文观测多场景示例 |
| tests | 数学、协议、交互事件与API回归测试 |
| tests/artifacts | 调试时保存的模型响应与调用证据，不含密钥 |

## 调试

运行`node src/tests/browser-harness.mjs`启动独立的固定响应测试服务。访问[测试页面](http://127.0.0.1:3001)，选择自定义服务，地址填写`http://127.0.0.1:3002/v1`，模型填写`ui-test-model`，测试密钥填写`local-ui-test-key`。

`tests/live-debug.mjs`用于人工授权后的真实接口检查，从标准输入读取配置，不把凭据写入文件。真实生成结果、题目语义和交互规则需要结合使用情境审阅；结构校验主要保证场景可渲染、计算可执行和引用有效。
