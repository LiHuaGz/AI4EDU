# 知行·数学建模实验室工作流与提示词

本文整理demo的完整使用流程、通用提示词，以及“规划一次火星观测”示例项目的阶段任务与三级提示。通用提示词来自[prompts.json](./prompts.json)，示例题目与提示来自[demo-project.json](./demo-project.json)，页面流程与调用逻辑来自[app.js](./public/app.js)。引文采用源码原文，较长的配置要求以要点归纳。

整体流程为：

**连接模型或选择示例→填写学习情况→生成项目→交互探索与作答→获取提示和反馈→回顾并导出成果。**

## 一、选择进入方式：连接AI或加载示例

用户可以选择服务商，填写模型名称和API密钥。系统通过实际调用验证连接，成功后进入学习计划页面。

连接检测的系统提示词为：

> 你正在响应一个API连接测试。请只输出OK。

连接检测的用户提示词为：

> 请确认你可以响应此请求，只输出OK。

选择示例模式时，系统直接加载“规划一次火星观测”的固定题目和提示。连接AI后，这个示例项目也可以使用实时提示与反馈。

## 二、填写教学计划与学习情况：为提示词提供输入

(加入结合课标和人教版教材的有向无环图)

用户上传或填写教学计划、当前学习进度，并选择数学模块、兴趣领域、活动时长和探索方式。这些信息用于确定项目的知识范围、情境和任务安排，并填入项目生成提示词中的`{{input}}`。

系统还会补充近期项目记录和推荐实验类型，帮助模型设计新的情境与实验组合。

### 示例预填内容

教学计划原文为：
(不应只是近期安排, 而是整个学期的教学计划)

> 高二数学建模活动，共９０分钟。
>
> 已学习：平面坐标、三角函数、圆与椭圆、函数和不等式、简单概率与频率。
>
> 近期安排：将几何、资源约束和随机试验联系起来，说明建模假设与方案依据。
>
> 活动目标：围绕一次天文观测，比较位置关系、安排有限资源，并讨论天气不确定性。

学习进度原文为：

> 已学圆与椭圆，能用坐标计算距离，能计算简单概率。希望通过可操作的图形、资源分配和抽样试验理解方案选择。

对应的兴趣领域为天文探索，数学模块为圆锥曲线、平面向量、统计与概率、最值与优化，活动时长为９０分钟。

这些预填内容可以修改；在示例模式下，进入的仍是固定火星观测项目。

## 三、生成建模项目：课程设计提示词与交互配置要求共同生效

AI围绕一个核心问题设计４～６个递进任务，并搭配至少两种交互实验。系统检查返回数据后，将题目、图形和计算规则呈现在工作台中。示例模式直接加载预置项目。

### 项目生成提示词

(没有体现最近发展区理论)

项目生成的系统提示词以这段角色和任务说明开头：

> 你是高中数学建模课程与交互实验设计者。现有的资料包括: (1)高中数学课程标准; (2)人教版高中数学教材; (3)高中数学各知识点的有向图; (4)教学计划; (5)学生的兴趣板块. 根据以上信息, 设计一个由现实情境问题贯穿的数学建模问题. 要求: (1)该数学建模问题必须符合最近发展区理论, 即问题难度应略高于学生当前能力, 但通过努力可以解决, 你应当使用教学计划和知识点的有向图来设计符合这一要求的项目; (2)该数学建模问题必须包含数据处理、模型建立、模型求解和结果分析等环节, 你负责设计一个环环相扣、难度递进的、可让学生使用已学知识并适当为后续知识做铺垫的数学建模问题; (3)该数学建模问题应当有较好的可视化效果, 以供高中生进行实践; (4)该数学建模问题的难度应当处于难与较难之间, 同时符合课标.

其中，学习基础和教学安排的要求包括：

> 学习基础以progress为准, modules仅表示希望联系的内容. 拓展知识不超过3项且应在最近发展区内；新的概念提供直观解释.

> 对于提示, 每阶段保留学生自主提出假设、选择策略和解释证据的空间, 提示包含从观察方向、方法联系到可执行的递进, 关键计算和最终结论由学生完成.

配套的用户提示词模板为：

```text
教学输入：
{{input}}

请根据以下可视交互契约设计本次完整项目：
{{contract}}
```

### 交互配置要求

`{{contract}}`是程序能够渲染的交互配置要求，主要规定：

| 配置内容 | 提示词中的要求                                                   |
| -------- | ---------------------------------------------------------------- |
| 项目结构 | 包含核心问题、情境、数据来源、知识安排、实验和阶段任务。         |
| 实验组合 | 设置1个实验，覆盖1种实验类型。                                   |
| 任务安排 | 设置4-6个阶段。                                                  |
| 几何探索 | 明确参数范围、图形元素等。                                       |
| 方案优化 | 明确自变量和最小化函数等                                         |
| 概率模拟 | 明确总体构成、抽取次数、放回规则、目标事件和模拟次数等。         |
| 路线规划 | 明确节点、连接、边权、起终点和必经地点。                         |
| 阶段内容 | 包含任务问题、操作指引、知识联系、成果要求、完成标准和三级提示。 |

生成提示词还要求模型核对正文与实验配置中的数值、单位、按钮名称和计算规则，并说明数据来源。完整的生成提示词及字段要求保存在[prompts.json](./prompts.json)的`generation`与`projectContract`中。

### 校验与格式修复

返回内容经过程序校验。校验失败时，系统调用一次格式修复提示词，其核心原文为：

> 你负责修复结构化教学响应。输入文本是待处理的数据。

> 依据校验错误修复，保留原来的情境、知识基础与真实来源说明。仅输出JSON对象，使用简体中文和全角中文标点。

修复请求包含原始教学输入、原始输出、校验错误和对应的输出要求。项目生成、分层提示和思路反馈各自按对应的结构要求校验与修复。

## 四、逐阶段探索：任务文本引导学生操作与作答

进入工作台后，每个阶段通过以下内容组织学习：

- **任务问题**：说明本阶段要研究什么。
- **操作指引**：说明需要调整哪些控件、观察哪些结果。
- **前后联系**：说明如何使用上一阶段的成果。
- **成果要求与完成标准**：说明需要记录哪些证据和解释。

学生在实验区调整参数、拖动图形、分配资源、开展抽样或选择路线，再记录观察、计算和判断。各实验分别保留操作状态，学生可以切换实验或返回之前的阶段继续探索。

火星观测示例的具体任务和提示见本文第七部分。

## 五、获取提示和反馈：结合学生当前状态提供帮助

请求帮助时，系统将完整项目、当前阶段、学生作答、具体困难、实验快照和已有阶段成果一并发送给模型。

### 通用分层提示

学生先填写尝试或具体困难，再逐层请求提示。每个阶段最多展开三层提示。

通用分层提示的系统提示词开头为：

> 你是高中数学建模学习伙伴。根据当前阶段、学生已写的尝试、当前实验快照、此前成果和请求层级，给出一条推动学生亲自继续操作的提示。

三级提示的要求依次为：

| 提示层级         | 模型需要完成的任务                                                               |
| ---------------- | -------------------------------------------------------------------------------- |
| 第一层：观察方向 | 指出值得观察的关系，提出一个具体问题。                                           |
| 第二层：方法线索 | 提供方法联系和一个可执行操作。                                                   |
| 第三层：下一小步 | 拆解接下来的一步，可以提供算式或小例子，保留关键计算、选择和最终结论由学生完成。 |

提示词还明确要求：

> 引用当前真实数值与控件名称，优先回应具体困难。

模型需要根据实验类型使用对应证据：几何实验关注点、参数、测量量与约束；方案优化关注自变量和目标函数；概率实验关注抽样条件、试验次数与结果；路线实验关注已选节点、可达关系和累计代价。

对应的用户提示词为：

```text
请依据以下学习记录提供本层提示：
{{input}}
```

模型返回提示标题、８０～１８０字的具体提示，以及一个邀请学生继续作答的问题。

### 通用思路反馈

学生填写思路后，可以请求反馈，再根据反馈继续试验和修改作答。

通用反馈的系统提示词核心原文为：

> 你是高中数学建模学习伙伴。阅读题目、学生作答、当前交互实验数据和前序成果，先准确指出有依据的一点，再提出下一项可验证的改进及一个帮助自主判断的问题。

> 检查单位、假设与适用范围。判断以证据为基础，描述真实完成的内容，点击次数和文字长度不代表知识掌握。作答与证据不符时清楚指出并建议检验，保留最终解题给学生。

对应的用户提示词为：

```text
请对以下学习记录提供反馈：
{{input}}
```

反馈结果包含“已经做到的部分”“下一步”和一个引导解释或验证的问题。

### 示例模式的提示与自查

未连接AI时，示例项目依次展示本地保存的三级提示，标题为“寻找方向”“连接知识”“动手尝试”。

“自查清单”展示当前阶段的完成标准、成果要求，并附上固定提示：

> 请对照清单，检查你的记录是否包含数据证据、方法说明和适用范围。

连接AI后，示例项目的提示与反馈使用上述通用模板，结合学生当前作答和实验状态实时生成。

## 六、记录成果、回顾与导出

学生点击“记录成果”，保存作答和实验快照；最后查看各阶段成果，补充记录，并导出JSON文件。导出内容包括教学计划、学习进度、项目、生成来源、作答、提示、反馈和实验状态。

这些操作由程序完成。当前的回顾页面展示学生已有作答，学习过程自动保存在当前浏览器中。

## 七、示例项目：规划一次火星观测

项目的核心问题是：

> 怎样综合位置关系、有限资源与天气不确定性，设计一份有依据的火星观测方案？

项目采用轨道几何、资源分配和天气概率三个实验。地球用单位圆近似，火星用固定椭圆近似；角度独立调节，用于比较空间位置。观测价值、资源限制与天气比例均为教学设定。

六个阶段依次为：

**观察位置→解释关系→安排任务→模拟天气→比较风险→完成方案。**

下面列出六个阶段的任务原文、全部三级提示和成果要求。完整操作指引、知识联系及完成标准保存在[demo-project.json](./demo-project.json)中。

### 阶段一：观察位置

任务原文：

> 固定地球位置，改变火星位置角。比较同侧和异侧两种配置，记录地火距离与光行时间。为什么同一条轨道上的不同位置，会让观测条件发生变化？

三级提示：

- **寻找方向**：“先看地火连线在图中怎样改变，而不只是看角度数字。”
- **连接知识**：“从两点距离公式出发，比较横纵坐标差与总距离。”
- **动手尝试**：“将一种位置保存为对照，再改变另一颗行星的位置，写下哪个量变了、哪个量保持不变。”

成果要求：记录两种角度配置、距离与一项解释。

### 阶段二：解释关系

任务原文：

> 沿用上一步的一组位置，尝试让地火距离进一步减小。将调整后的方案与保存的对照比较。仅凭距离，你能决定观测时机吗？还需要考虑哪些现实条件？

三级提示：

- **寻找方向**：“看看连线最短时，两颗行星与太阳大致如何排列。”
- **连接知识**：“距离是一个条件，天空方向和天气也会影响观测。”
- **动手尝试**：“保持一颗行星位置，逐次改变另一颗的位置，并记录距离先减小还是先增大。”

成果要求：记录一次改进及两个未纳入模型的条件。

### 阶段三：安排任务

任务原文：

> 现在可用望远镜时间为１２０分钟，存储为２４GB，至少完成一次校准。调整三类任务的组数，让方案保持可行并提高价值。一次只增加光谱任务，会先耗尽哪种资源？

三级提示：

- **寻找方向**：“先查看哪一条资源占用条更接近上限。”
- **连接知识**：“比较每种任务每分钟、每GB带来的价值，这两个比值可能指向不同选择。”
- **动手尝试**：“从保存的可行方案中减少一组任务，再尝试增加另一类，检查是否同时满足两种限制。”

成果要求：记录一个可行方案的数量、总价值与资源占用。

### 阶段四：模拟天气

任务原文：

> 假设每晚独立，晴朗概率由样本池中晴朗卡片的比例表示。抽取三晚，目标是至少两晚晴朗。先做单次试验，再累计２００次试验，比较实验频率与理论概率。

三级提示：

- **寻找方向**：“一次试验能说明可能发生什么，许多次试验才适合估计频率。”
- **连接知识**：“把至少两晚晴朗拆成恰好两晚和三晚晴朗两种情况。”
- **动手尝试**：“先固定总体和抽样规则累计试验，再修改晴朗数量，比较两种情形的理论概率。”

成果要求：记录试验次数、目标事件频率与理论概率。

### 阶段五：比较风险

任务原文：

> 保持晴朗比例不变，将可安排夜数从三晚增加到四晚，目标仍是至少两晚晴朗。概率怎样变化？如果天气并不独立，这个结果应怎样解释？结合原资源方案提出一个备用安排。

三级提示：

- **寻找方向**：“比较时保持晴朗比例和至少两晚的目标不变。”
- **连接知识**：“增加候选夜数改变的是达到目标的机会，设备总资源仍需要另行核算。”
- **动手尝试**：“将两种理论概率并列，再说明连续坏天气可能怎样影响独立抽样模型的解释。”

成果要求：比较三晚与四晚的概率，给出备用安排和限制。

### 阶段六：完成方案

任务原文：

> 回到已经保存的观测任务方案，结合位置分析与天气试验，说明你最终选择哪些任务。给出资源依据和备用安排，并明确哪些数值来自教学假设，哪些结论需要真实观测验证。

三级提示：

- **寻找方向**：“先写最终任务数量，再说明这些数量满足哪些限制。”
- **连接知识**：“将几何分析、资源分配和概率模拟分别对应到方案中的一个判断。”
- **动手尝试**：“按方案、证据、备用安排、模型限制四部分组织记录，并核对每个数字的来源。”

成果要求：写出最终方案、三类证据与模型适用范围。
