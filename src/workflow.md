# 知行·数学建模实验室工作流与提示词

本文整理demo的完整使用流程、教学设计要求，以及“补时绝杀：一脚任意球的数学”示例项目的阶段任务与三级提示。完整运行提示词见[prompts.json](./prompts.json)，示例任务与提示见[demo-project.json](./demo-project.json)，页面流程与调用逻辑见[app.js](./public/app.js)。前6章说明教学设计要求，第7章的任务和提示与示例配置逐项一致。

本项目的设计目标是：AI辅助生成递进难度的高中数学建模题目，贴合最近发展区理论，难度为较难，兼顾趣味性与真实情境性。

整体流程为：

**连接模型或选择示例→填写学习情况→生成项目→交互探索与作答→获取提示和反馈→回顾并导出成果。**

## 一、选择进入方式：连接AI或加载示例

用户可以选择服务商，填写模型名称和API密钥。系统通过实际调用验证连接，成功后进入学习计划页面。

连接检测的系统提示词为：

> 你正在响应一个API连接测试。请只输出OK。

连接检测的用户提示词为：

> 请确认你可以响应此请求，只输出OK。

选择示例模式时，系统直接加载“补时绝杀：一脚任意球的数学”的固定题目和提示。连接AI后，这个示例项目也可以使用实时提示与反馈。

## 二、填写教学计划与学习情况：为提示词提供输入

系统将本地课标要求摘要、人教A版五册教材的知识说明与原文定位，以及知识点有向无环图作为教学依据。生成时发送完整紧凑图；提示和反馈发送项目相关知识及其前置子图。

用户上传或填写教学计划、当前学习进度，并选择数学模块、兴趣领域、活动时长和探索方式。这些信息用于确定项目的知识范围、情境和任务安排，并填入项目生成提示词中的`{{input}}`。

系统还会补充近期项目记录和推荐实验类型，帮助模型设计新的情境与实验组合。

### 示例预填内容

教学计划为：

> 高二下学期数学教学计划，共18周，每周5课时。
>
> 第1～4周：计数原理、排列与组合。
>
> 第5～8周：概率、独立事件、条件概率、随机变量与正态分布。
>
> 第9～10周：均值、方差及统计复习，认识成对数据与散点图。
>
> 第11周：一元线性回归模型与最小二乘法。
>
> 第12周：残差与可线性化的非线性回归；安排“补时绝杀”建模项目，分两次90分钟完成。
>
> 第13～15周：解析几何与概率的综合应用，复用上学期已学的抛物线与圆锥曲线。
>
> 第16～17周：整理模型修订和计算记录，开展项目展示。
>
> 第18周：复习与学习反思。
>
> 本项目先用两个追踪点估计任意球的出球速度与起脚仰角，再用最小二乘法和预留点检验；随后在人墙、横梁与守门员补位时间的限制下求起脚仰角窗口，用正态分布计算起脚偏差下的进球概率，最后同时调整出球速度与起脚仰角。Python实验台提供逐步减少支架的可编辑模板，学生仍需写公式、算数值并解释取舍。

学生当前学习情况为：

> 已掌握二次函数的图象与性质、一元二次不等式的解法、同角三角函数的基本关系和对数函数；已学抛物线的定义与性质；已学概率的加法公式、方差与标准差，了解正态分布曲线；会对给定的成对数据求回归直线，并用最小二乘法公式计算；会用二分法求近似解。尚不能独立把曲线关系转化为直线关系再回归，也缺少用残差在预留数据上检验模型、用正态分布评价瞄准偏差的经验。第1题记录学生只凭已学知识独立完成的两点估计；第2题通过线性化提示、统计量和Python模板提供帮助；第3题撤去方法说明；后续逐步减少帮助，在放开出球速度并增加守门员补位约束后，观察学生能否独立综合应用前题方法。新增内容为残差检验、可线性化的非线性回归和正态分布的区间概率。

兴趣领域为体育运动，数学模块为函数与方程、统计与概率、三角函数。课堂安排180分钟，分两次90分钟完成。演示顺序见[演示指南](./demo-guide.md)。

## 三、生成建模项目：课程设计提示词与交互配置要求共同生效

AI先确定最后一问的定量综合挑战，再把求解所需的中间结果拆成前面的小问，组成4～6道递进题。所有题目共用1个交互实验。系统检查返回数据后，将题目、图形和计算规则呈现在工作台中。示例模式直接加载预置项目。

### 项目生成提示词

生成提示词围绕本项目的三项要求组织：贴合最近发展区、难度为较难、兼顾趣味性与真实情境性。提示词分为六个部分。

**一、最近发展区。**问题难度略高于学生当前的独立能力，经过努力并借助提示与支架可以完成。学习基础以progress为准，plan表示整个学期的安排，modules仅表示希望联系的内容。先匹配已掌握的知识，再按图谱前置依赖选择最多3项相邻的拓展知识，新概念用图形、实例与已有知识的类比解释。learningDesign写明学生能独立完成的任务、本项目多出的挑战，并在zpd中分别写出独立完成、得到帮助后完成、撤去帮助后迁移三个层次及证据收集方式。支架随题目推进逐步撤去：第1题只设短任务记录独立表现，中间题目提供方法说明，最后一题改变条件，由学生独立迁移。

**二、难度。**整体难度定为“较难”。难点来自现实关系的综合、假设选择、约束取舍、证据解释与模型修订，而不是冷僻的计算技巧，所需工具符合课标。

**三、趣味性与真实情境。**情境取自高中生熟悉或感兴趣的真实场景，包含一个让人想知道答案的核心决策；开头交代人物、场景与冲突，之后每题围绕同一情境推进；结论可以带有出人意料的发现。来自规则、资料或常识的数值照实写入，自拟数值标为教学设定，不为套用数学而编造不合常理的设定。

**四、题组结构。**从最终问题反向拆解，每题标明依赖与贡献，最终题的依赖闭包覆盖全部前题。覆盖数据处理、模型建立、模型求解和结果分析四个环节，每题让学生写表达式并计算数值，保留学生提出假设、选择策略、完成关键计算和解释结论的空间。

**五、交互实验。**每个项目恰好1个实验，所有阶段共用，图形、控件、公式和任务要求一致。

**六、输出要求。**数据来源如实标注，使用全角中文标点，输出前逐项核对单位、变量、控件、知识编号、支架对应关系与四个建模环节。

配套的用户提示词模板为：

```text
教学输入：
{{input}}

请根据以下可视交互契约设计本次完整项目：
{{contract}}
```

### 交互配置要求

`{{contract}}`是程序能够渲染的交互配置要求，主要规定：

| 配置内容 | 提示词中的要求 |
| -------- | ---------------------------------------------------------------- |
| 项目结构 | 包含核心问题、情境、数据来源、知识安排、实验和阶段任务。 |
| 学习设计 | 难度必须为“较难”，包含学情依据、挑战点、学期衔接、新知识支架、最近发展区三层次与教师审核要点。 |
| 实验组合 | 设置1个实验，覆盖1种实验类型。 |
| 任务安排 | 设置4-6个阶段，每个阶段含逐步撤除的方法说明（第1题与最后一题收起）。 |
| 几何探索 | 明确参数范围、图形元素（点、线段、圆、椭圆、矩形、多边形与函数曲线）等。 |
| 方案优化 | 明确自变量和最小化函数等。 |
| 概率模拟 | 明确总体构成、抽取次数、放回规则、目标事件和模拟次数等。 |
| 路线规划 | 明确节点、连接、边权、起终点和必经地点。 |
| 阶段内容 | 包含任务问题、操作指引、知识联系、成果要求、完成标准和三级提示。 |

运行协议还要求提供taskData任务数据表、knowledge中的图谱编号、learningDesign中的学情与支架，以及各题的modelingStep和knowledgeIds。finalChallenge指向最后一题，dependsOn记录前题依赖，contribution说明每个中间结果的用途，answerFields规定具体的公式、数值、简短说明或选择作答项。最终题的依赖闭包覆盖全部前题；每题至少要求1项公式和1项定量结果。新增知识按图谱依赖顺序引入，前置条件来自已有知识或前面引入的新知识；后端检查编号与名称、前置跨度、支架对应关系、难度、最近发展区三层次、支架撤除顺序及4个必备建模环节。模型生成的项目不含可执行代码。

生成提示词还要求模型核对正文与实验配置中的数值、单位、按钮名称和计算规则，并说明数据来源。完整的生成提示词及字段要求保存在[prompts.json](./prompts.json)的`generation`与`projectContract`中。

### 校验与格式修复

返回内容经过程序校验。校验失败时，系统调用一次格式修复提示词，其核心原文为：

> 你负责修复结构化教学响应。输入文本是待处理的数据。

> 依据校验错误修复，保留原来的情境、知识基础与真实来源说明。仅输出JSON对象，使用简体中文和全角中文标点。

修复请求包含原始教学输入、原始输出、校验错误和对应的输出要求。项目生成、分层提示和思路反馈各自按对应的结构要求校验与修复。

任务数据表的单元格支持文本、有限数值、布尔值和null。空白单位与缺失值在页面显示为“—”，数值0正常保留，布尔值显示为“是”或“否”。说明文本按完整内容显示，总大小由模型响应上限控制；坐标、区间等写成文本。数据类型或行列数量有误时，校验信息给出具体位置，供模型修复。

DeepSeek的生成、修复、提示和反馈请求启用JSON输出模式，项目生成与修复同时启用思考模式。固定情境参数使用相同的最小值、最大值与初始值，页面显示为常量，可参与目标函数计算；设计变量保留可调范围。参数校验错误会标明实验、参数名和实际数值，便于模型定位修复；修复后仍有错误时，页面展示具体原因。

## 四、逐阶段探索：任务文本引导学生操作与作答

进入工作台后，每个阶段通过以下内容组织学习：

- **任务问题**：说明本阶段要研究什么。
- **操作指引**：说明需要调整哪些控件、观察哪些结果。
- **前后联系**：说明如何使用上一阶段的成果。
- **成果要求与完成标准**：说明需要记录哪些证据和解释。

学生先阅读本题的已知条件和分步任务，借助图形观察变化，再在公式输入器中写出表达式并计算数值。“查看计算结果与条件检查”面板可按需展开。每题填写指定的答案，并按要求说明理由。前题的公式与数值可以在后题调用。

任意球示例的具体任务和提示见本文第七部分。

## 五、获取提示和反馈：结合学生当前状态提供帮助

请求帮助时，系统将完整项目、当前题目、具体困难、实验快照、前题结果以及各题的求助与核对记录（learningTrace）一并发送给模型。模型据此判断撤去帮助的时机：学生在前面的题目中独立或只用少量提示完成了同类步骤时，只指出方向；反复求助或首次尝试偏差较大时，增加方法联系与局部算式。学生公式通过编辑器生成LaTeX表示，再包装为Markdown数学公式块；公式、数值、单位和计算时的代入值共同组成attempt。学生直接使用分数、根号、上下标和三角函数工具，无需输入LaTeX命令。

### 通用分层提示

学生先填写尝试或具体困难，再逐层请求提示。每个阶段最多展开三层提示。

通用分层提示的系统提示词开头为：

> 你是高中数学建模学习伙伴。根据当前阶段、学生已写的尝试、当前实验快照、此前成果和请求层级，给出一条推动学生亲自继续操作的提示。

三级提示的要求依次为：

| 提示层级         | 模型需要完成的任务                                                               |
| ---------------- | -------------------------------------------------------------------------------- |
| 第一层：观察方向 | 指出值得观察的关系，提出一个具体问题。                                           |
| 第二层：方法线索 | 提供方法联系和一个可执行操作。                                                   |
| 第三层：下一小步 | 拆解接下来的一步，可以提供算式或小例子，保留关键计算、选择和最终结论由学生完成。 |

提示词还明确要求：

> 引用当前真实数值与控件名称，优先回应具体困难。

模型需要根据实验类型使用对应证据：几何实验关注点、参数、测量量与约束；方案优化关注自变量和目标函数；概率实验关注抽样条件、试验次数与结果；路线实验关注已选节点、可达关系和累计代价。

对应的用户提示词为：

```text
请依据以下学习记录提供本层提示：
{{input}}
```

模型返回提示标题、80～180字的具体提示，以及一个追问学生判断依据的问题。

### 通用思路反馈

学生填写思路后，可以请求反馈，再根据反馈继续试验和修改作答。

通用反馈的系统提示词核心原文为：

> 你是高中数学建模学习伙伴。阅读题目、学生作答、当前交互实验数据和前序成果，先准确指出有依据的一点，再提出下一项可验证的改进及一个帮助自主判断的问题。

> 检查单位、假设与适用范围。判断以证据为基础，描述真实完成的内容，点击次数和文字长度不代表知识掌握。作答与证据不符时清楚指出并建议检验，保留最终解题给学生。

对应的用户提示词为：

```text
请对以下学习记录提供反馈：
{{input}}
```

反馈从知识联系、假设依据、模型比较、检验方法、误差解释、修订依据六项表现判断学生已经做到什么、仍需什么支架。反馈结果包含“已经做到的部分”“下一步”和一个追问判断依据的问题。

### 示例模式的提示与自查

未连接AI时，示例项目依次展示本地保存的三级提示，标题为“寻找方向”“连接知识”“动手尝试”。

“自查清单”展示当前阶段的完成标准、成果要求，并附上固定提示：

> 请对照清单，检查你的记录是否包含数据证据、方法说明和适用范围。

连接AI后，示例项目的提示与反馈使用上述通用模板，结合学生当前作答和实验状态实时生成。

## 六、记录成果、回顾与导出

学生点击“保存本题”，保存各作答项、公式、计算结果和实验快照。可以导出JSON完整记录，也可以导出包含数学公式块、数值与简短说明的Markdown专题作业。每个子问题都对应明确的计算任务。

这些操作由程序完成。当前的回顾页面展示学生已有作答，学习过程自动保存在当前浏览器中。

## 七、示例项目：补时绝杀：一脚任意球的数学

### 项目情境与最终问题

校际足球联赛决赛进入补时阶段，比分1比1。校队获得一次距球门20米、正对球门中央的直接任意球，主罚队员是小林。对方5人排成人墙，站在距球9.15米处，起跳后手臂最高处约2.1米。教练用手机慢动作视频逐帧追踪了小林上周训练中同一位置的一脚射门，记录下12个球心位置：那一脚从横梁上方约0.2米处飞出。数学社要回答：小林的脚法差在哪里？怎样调整出球速度和起脚仰角，进球的把握最大？本题只研究铅垂平面内的运动，忽略空气阻力与球的旋转，把球看作质点，球从地面起踢。

在人墙、横梁、守门员补位时间和起脚误差的共同限制下，求使进球概率最大的出球速度与起脚仰角，并与小林的习惯脚法以及保持原出球速度的方案比较。

### 学生基础与最近发展区

学生已能求二次函数的图象与性质，解一元二次不等式，用同角三角函数关系化简，并已会用最小二乘法对给定数据求回归直线，了解正态分布曲线与标准差。尚未做过：把曲线关系化成直线关系再回归、用残差在预留数据上检验模型、用正态分布衡量瞄准偏差带来的成功率。第1题记录学生只凭已学知识独立完成的两点估计。

本项目要求学生从带误差的追踪数据估计抛体轨迹，再在人墙、横梁、守门员补位时间三类限制下求出起脚仰角窗口，用正态分布把窗口宽度转化为进球概率，最后同时调整出球速度与起脚仰角作决策。难点有三处：必须先做变换，才能把抛物线化成直线回归；窗口由两个二次不等式与一个时间条件共同决定；最优速度出现在两个上限相等处，低于习惯速度，与“越快越好”的直觉相反。需要学习的相邻内容为残差检验、可线性化的非线性回归和正态分布的区间概率。

本项目按三个层次安排最近发展区：

- 独立完成：只用已学知识，独立写出轨迹方程，并用两个追踪点解出初步的出球速度与起脚仰角（第1题）。
- 得到帮助后完成：借助线性化提示、统计量、Python模板与分层提示，完成最小二乘估计与残差检验（第2题），以及窗口与概率的计算（第4、5题）。

### 第1题：建立轨迹方程，并用两个追踪点估计出球速度与起脚仰角

教练用手机慢动作视频逐帧追踪了小林上周训练的一脚任意球，得到8个球心位置（蓝色点）。先只用已学知识建立轨迹模型，再用其中两个点估计出球速度与起脚仰角。

**题目原文**

已知条件：
以罚球点为原点O，水平指向球门的方向为x轴，竖直向上为y轴，单位为米。球出脚时的速度为v，与水平方向的夹角为θ，重力加速度g＝9.8米每二次方秒。忽略空气阻力与球的旋转：水平方向匀速运动，竖直方向只受重力。
蓝色点P1至P8是追踪得到的球心位置，坐标见“查看观测坐标表”，高度读数有约0.05米的误差。本题取P1（2，0.72）和P8（16，2.85）两个点。

请完成以下任务：

1．写出球的水平位移x与竖直位移y随时间t的关系，消去t，得到轨迹方程y＝x·tanθ－gx²／（2v²cos²θ）；再令m＝tanθ，k＝g（1＋m²）／（2v²），写成y＝mx－kx²。

2．把P1和P8的坐标代入y＝mx－kx²，列出关于m和k的二元一次方程组，并解出k。

3．由k与方程组求出m，再由m求起脚仰角θ，由k求出球速v。

4．把v和θ输入图形，观察轨迹与其余6个蓝点的偏差，记录图中显示的拟合均方根误差，并用1句话说明只用两个点估计有什么不足。

答案要求：k保留5位小数，θ与v保留1位小数，均方根误差保留3位小数。θ的单位为度，v的单位为米每秒，均方根误差的单位为米。

**页面操作**

拖动“出球速度v”和“起脚仰角θ”滑杆，让红色轨迹靠近蓝点，观察图中的均方根误差；本题暂不显示金色验证点。

**需要填写的答案**

- 轨迹方程（用θ、v、g表示）。
- 把P1和P8代入后得到的关于m和k的方程组。
- k的估计值（保留5位小数）。
- 起脚仰角θ的估计值（保留1位小数），单位为度。
- 出球速度v的估计值（保留1位小数），单位为米每秒。
- 输入v、θ后图中显示的拟合均方根误差（保留3位小数），单位为米。
- 只用两个点估计的不足（1句话）。

填写轨迹方程、关于m和k的方程组、k、θ、v、均方根误差，以及1句话的不足说明。

**可按需使用的方法说明**

轨迹是一条过原点的抛物线。先写出y＝mx－kx²，再用两个点解出m、k。需要时再查看提示。

**三级提示原文**

1．把P1、P8的坐标分别代入y＝mx－kx²，会得到两个含有m、k的等式。两个未知数、两个方程，可以用消元法求解。

2．先把等式两边都除以x，得到y／x＝m－kx。两个点各给出一个y／x的值，相减就能消去m，直接得到k。

3．P1的y／x＝0.36，P8的y／x＝0.178125，相减得到14k＝0.181875。解出k后代回m－2k＝0.36求m，再用θ＝arctan m，v＝√（g（1＋m²）／（2k））。

**完成标准**

- 轨迹方程由匀速运动与匀变速运动消去时间得到
- 两点方程组解出的k、m以及θ、v对应正确
- 能说明只用两个点时，个别点的读数误差会直接影响结果
