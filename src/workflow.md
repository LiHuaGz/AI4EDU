# 知行·数学建模实验室工作流与提示词

本文整理demo的完整使用流程、教学设计要求，以及“极光号卫星通信：轨道拟合与方案设计”示例项目的阶段任务与三级提示。完整运行提示词见[prompts.json](./prompts.json)，示例任务与提示见[demo-project.json](./demo-project.json)，页面流程与调用逻辑见[app.js](./public/app.js)。前6章说明教学设计要求，第7章的任务和提示与示例配置逐项一致。

整体流程为：

**连接模型或选择示例→填写学习情况→生成项目→交互探索与作答→获取提示和反馈→回顾并导出成果。**

## 一、选择进入方式：连接AI或加载示例

用户可以选择服务商，填写模型名称和API密钥。系统通过实际调用验证连接，成功后进入学习计划页面。

连接检测的系统提示词为：

> 你正在响应一个API连接测试。请只输出OK。

连接检测的用户提示词为：

> 请确认你可以响应此请求，只输出OK。

选择示例模式时，系统直接加载“极光号卫星通信：轨道拟合与方案设计”的固定题目和提示。连接AI后，这个示例项目也可以使用实时提示与反馈。

## 二、填写教学计划与学习情况：为提示词提供输入

系统将本地课标要求摘要、人教A版五册教材的知识说明与原文定位，以及知识点有向无环图作为教学依据。生成时发送完整紧凑图；提示和反馈发送项目相关知识及其前置子图。

用户上传或填写教学计划、当前学习进度，并选择数学模块、兴趣领域、活动时长和探索方式。这些信息用于确定项目的知识范围、情境和任务安排，并填入项目生成提示词中的`{{input}}`。

系统还会补充近期项目记录和推荐实验类型，帮助模型设计新的情境与实验组合。

### 示例预填内容

教学计划为：

> 高二下学期数学教学计划，共18周，每周5课时。
>
> 第1～4周：计数原理、排列与组合。
>
> 第5～8周：概率、独立事件、条件概率与随机变量。
>
> 第9～10周：均值、方差及统计复习，认识成对数据与散点图。
>
> 第11～12周：回归模型、最小二乘与残差，安排“极光号”建模项目，分两次90分钟完成。
>
> 第13～15周：解析几何与概率的综合应用，复用上学期已学的圆锥曲线。
>
> 第16～17周：整理模型修订和计算记录，开展项目展示。
>
> 第18周：复习与学习反思。
>
> 本项目首先从8个离散观测点拟合圆或椭圆，锁定后用4个预留点检验；再结合通信边界与概率计算，处理最低仰角升级和最多3次发送的决策。Python实验台提供逐步减少支架的可编辑模板，学生仍需写公式、算数值并解释取舍。

学生当前学习情况为：

> 已掌握概率加法、独立事件乘法、频率估计、平均数与方差，能阅读散点图；已学椭圆定义、标准方程与几何性质，能独立完成标准椭圆题，并会用单调性和二分法求近似解。尚不能独立从带误差的离散数据建立椭圆模型，也缺少使用预留数据检验、根据通信条件计算发送成功概率的经验。第1题记录学生独立完成的初步拟合；第2题通过焦点关系说明、统计量和Python模板提供帮助；后续逐步减少帮助，在改变通信条件后观察学生能否独立应用前题方法。新增内容为一元回归与随机误差、最小二乘法和残差检验。

兴趣领域为天文探索，数学模块为圆锥曲线、统计与概率、最值与优化。课堂安排180分钟，分两次90分钟完成。演示顺序见[演示指南](./demo-guide.md)。

## 三、生成建模项目：课程设计提示词与交互配置要求共同生效

AI先确定最后一问的定量综合挑战，再把求解所需的中间结果拆成前面的小问，组成4～6道递进题。所有题目共用1个交互实验。系统检查返回数据后，将题目、图形和计算规则呈现在工作台中。示例模式直接加载预置项目。

### 项目生成提示词

最近发展区通过已有知识、新增知识、前置依赖和学习支架共同体现；模型需要给出学情依据、挑战点和整学期衔接说明。

项目生成的系统提示词以这段角色和任务说明开头：

> 你是高中数学建模课程与交互实验设计者。现有的资料包括: (1)高中数学课程标准; (2)人教版高中数学教材; (3)高中数学各知识点的有向图; (4)教学计划; (5)学生的兴趣板块. 根据以上信息, 设计一个由现实情境问题贯穿的数学建模问题. 要求: (1)该数学建模问题必须符合最近发展区理论, 即问题难度应略高于学生当前能力, 但通过努力可以解决, 你应当使用教学计划和知识点的有向图来设计符合这一要求的项目; (2)该数学建模问题必须包含数据处理、模型建立、模型求解和结果分析等环节, 你负责设计一个环环相扣、难度递进的、可让学生使用已学知识并适当为后续知识做铺垫的数学建模问题; (3)该数学建模问题应当有较好的可视化效果, 以供高中生进行实践; (4)该数学建模问题的难度应当处于难与较难之间, 同时符合课标.

其中，学习基础和教学安排的要求包括：

> 学习基础以progress为准, modules仅表示希望联系的内容. 拓展知识不超过3项且应在最近发展区内；新的概念提供直观解释.

> 对于提示, 每阶段保留学生自主提出假设、选择策略和解释证据的空间, 提示包含从观察方向、方法联系到可执行的递进, 关键计算和最终结论由学生完成.

配套的用户提示词模板为：

```text
教学输入：
{{input}}

请根据以下可视交互契约设计本次完整项目：
{{contract}}
```

### 交互配置要求

`{{contract}}`是程序能够渲染的交互配置要求，主要规定：

| 配置内容 | 提示词中的要求                                                   |
| -------- | ---------------------------------------------------------------- |
| 项目结构 | 包含核心问题、情境、数据来源、知识安排、实验和阶段任务。         |
| 实验组合 | 设置1个实验，覆盖1种实验类型。                                   |
| 任务安排 | 设置4-6个阶段。                                                  |
| 几何探索 | 明确参数范围、图形元素等。                                       |
| 方案优化 | 明确自变量和最小化函数等                                         |
| 概率模拟 | 明确总体构成、抽取次数、放回规则、目标事件和模拟次数等。         |
| 路线规划 | 明确节点、连接、边权、起终点和必经地点。                         |
| 阶段内容 | 包含任务问题、操作指引、知识联系、成果要求、完成标准和三级提示。 |

运行协议还要求提供taskData任务数据表、knowledge中的图谱编号、learningDesign中的学情与支架，以及各题的modelingStep和knowledgeIds。finalChallenge指向最后一题，dependsOn记录前题依赖，contribution说明每个中间结果的用途，answerFields规定具体的公式、数值、简短说明或选择作答项。最终题的依赖闭包覆盖全部前题；每题至少要求1项公式和1项定量结果。新增知识按图谱依赖顺序引入，前置条件来自已有知识或前面引入的新知识；后端检查编号与名称、前置跨度、支架对应关系及4个必备建模环节。

生成提示词还要求模型核对正文与实验配置中的数值、单位、按钮名称和计算规则，并说明数据来源。完整的生成提示词及字段要求保存在[prompts.json](./prompts.json)的`generation`与`projectContract`中。

### 校验与格式修复

返回内容经过程序校验。校验失败时，系统调用一次格式修复提示词，其核心原文为：

> 你负责修复结构化教学响应。输入文本是待处理的数据。

> 依据校验错误修复，保留原来的情境、知识基础与真实来源说明。仅输出JSON对象，使用简体中文和全角中文标点。

修复请求包含原始教学输入、原始输出、校验错误和对应的输出要求。项目生成、分层提示和思路反馈各自按对应的结构要求校验与修复。

任务数据表的单元格支持文本、有限数值、布尔值和null。空白单位与缺失值在页面显示为“—”，数值0正常保留，布尔值显示为“是”或“否”。说明文本按完整内容显示，总大小由模型响应上限控制；坐标、区间等写成文本。数据类型或行列数量有误时，校验信息给出具体位置，供模型修复。

DeepSeek的生成、修复、提示和反馈请求启用JSON输出模式，项目生成与修复同时启用思考模式。固定情境参数使用相同的最小值、最大值与初始值，页面显示为常量，可参与目标函数计算；设计变量保留可调范围。参数校验错误会标明实验、参数名和实际数值，便于模型定位修复；修复后仍有错误时，页面展示具体原因。

## 四、逐阶段探索：任务文本引导学生操作与作答

进入工作台后，每个阶段通过以下内容组织学习：

- **任务问题**：说明本阶段要研究什么。
- **操作指引**：说明需要调整哪些控件、观察哪些结果。
- **前后联系**：说明如何使用上一阶段的成果。
- **成果要求与完成标准**：说明需要记录哪些证据和解释。

学生先阅读本题的已知条件和分步任务，借助图形观察变化，再在公式输入器中写出表达式并计算数值。“查看计算结果与条件检查”面板可按需展开。每题填写指定的答案，并按要求说明理由。前题的公式与数值可以在后题调用。

卫星通信示例的具体任务和提示见本文第七部分。

## 五、获取提示和反馈：结合学生当前状态提供帮助

请求帮助时，系统将完整项目、当前题目、具体困难、实验快照和前题结果一并发送给模型。学生公式通过编辑器生成LaTeX表示，再包装为Markdown数学公式块；公式、数值、单位和计算时的代入值共同组成attempt。学生直接使用分数、根号、上下标和三角函数工具，无需输入LaTeX命令。

### 通用分层提示

学生先填写尝试或具体困难，再逐层请求提示。每个阶段最多展开三层提示。

通用分层提示的系统提示词开头为：

> 你是高中数学建模学习伙伴。根据当前阶段、学生已写的尝试、当前实验快照、此前成果和请求层级，给出一条推动学生亲自继续操作的提示。

三级提示的要求依次为：

| 提示层级         | 模型需要完成的任务                                                               |
| ---------------- | -------------------------------------------------------------------------------- |
| 第一层：观察方向 | 指出值得观察的关系，提出一个具体问题。                                           |
| 第二层：方法线索 | 提供方法联系和一个可执行操作。                                                   |
| 第三层：下一小步 | 拆解接下来的一步，可以提供算式或小例子，保留关键计算、选择和最终结论由学生完成。 |

提示词还明确要求：

> 引用当前真实数值与控件名称，优先回应具体困难。

模型需要根据实验类型使用对应证据：几何实验关注点、参数、测量量与约束；方案优化关注自变量和目标函数；概率实验关注抽样条件、试验次数与结果；路线实验关注已选节点、可达关系和累计代价。

对应的用户提示词为：

```text
请依据以下学习记录提供本层提示：
{{input}}
```

模型返回提示标题、80～180字的具体提示，以及一个邀请学生继续作答的问题。

### 通用思路反馈

学生填写思路后，可以请求反馈，再根据反馈继续试验和修改作答。

通用反馈的系统提示词核心原文为：

> 你是高中数学建模学习伙伴。阅读题目、学生作答、当前交互实验数据和前序成果，先准确指出有依据的一点，再提出下一项可验证的改进及一个帮助自主判断的问题。

> 检查单位、假设与适用范围。判断以证据为基础，描述真实完成的内容，点击次数和文字长度不代表知识掌握。作答与证据不符时清楚指出并建议检验，保留最终解题给学生。

对应的用户提示词为：

```text
请对以下学习记录提供反馈：
{{input}}
```

反馈结果包含“已经做到的部分”“下一步”和一个引导解释或验证的问题。

### 示例模式的提示与自查

未连接AI时，示例项目依次展示本地保存的三级提示，标题为“寻找方向”“连接知识”“动手尝试”。

“自查清单”展示当前阶段的完成标准、成果要求，并附上固定提示：

> 请对照清单，检查你的记录是否包含数据证据、方法说明和适用范围。

连接AI后，示例项目的提示与反馈使用上述通用模板，结合学生当前作答和实验状态实时生成。

## 六、记录成果、回顾与导出

学生点击“保存本题”，保存各作答项、公式、计算结果和实验快照。可以导出JSON完整记录，也可以导出包含数学公式块、数值与简短说明的Markdown专题作业。每个子问题都对应明确的计算任务。

这些操作由程序完成。当前的回顾页面展示学生已有作答，学习过程自动保存在当前浏览器中。

## 七、示例项目：极光号卫星通信：轨道拟合与方案设计

### 项目情境与最终问题

极光号科考船需要通过卫星向岸站发送海冰图像。本题提供8个带测量误差的卫星位置观测点，另有4个点用于检验拟合结果。假定轨道位于给定平面内，长轴沿横轴，地心是左焦点。首先估计卫星当前的轨道，再比较改变轨道参数或缩小通信区间的方案。船体遮挡有两种情况：最低通信仰角为5°或8°，发生概率分别为0.8和0.2。一次任务期间遮挡情况保持不变。消息可能在指定轨道段的任意位置产生，并需要立即发送；最多3次短时间发送期间，卫星位置近似不变。目标是在该轨道段的每个位置，至少成功发送一次的概率均达到99％。

卫星在参数角−20°≤θ≤20°的轨道段内，需要随时向两个站点转发消息。半长轴a≤9.3千公里，最多发送3次。能否使每个位置的成功概率都达到99％？请计算并比较两种方案：保持a≤9.3、缩小通信区间；保持−20°≤θ≤20°、提高半长轴上限。

### 学生基础与最近发展区

学生已掌握概率加法、独立事件乘法、频率估计、平均数与方差，能够阅读散点图；能独立解标准椭圆题，理解焦点、半轴和离心率。第1题记录学生使用这些知识初步拟合观测点的表现。

本项目要求学生从带误差的数据估计椭圆参数，并用预留数据检查拟合效果，再把轨道模型用于通信与概率判断。需要学习的相邻内容包括一元回归与随机误差、最小二乘法、残差检验；椭圆性质和基础概率计算来自已学知识。

最近发展区关注学生独立解决问题的水平与得到帮助后能够达到的水平之间的差距，参见[Vygotsky《Mind in Society》第86～87页](https://home.fau.edu/musgrove/web/vygotsky1978.pdf)。本项目先记录学生的初步拟合，再提供焦点关系说明、参数估计所需的统计量、Python模板和逐步提示。第2题核对通过且填写完整后，第3题的方法说明默认收起；最后一题要求学生在改变条件后独立比较方案。

依据学生表现调整帮助、逐步减少帮助和交还任务责任的设计，参考[van de Pol等关于教学支架的综述](https://research.vu.nl/en/publications/scaffolding-in-teacher-student-interaction-a-decade-of-research/)。页面保留首次记录、所用帮助及核对结果；教师还需结合公式与解释判断学生的学习情况。

### 题目中的数据与符号

| 任务信息 | 数值 | 约定 |
| --- | --- | --- |
| 用于拟合的观测点 | 8 | 蓝色点P1至P8，坐标见“查看观测坐标表” |
| 用于检验的观测点 | 4 | 金色点V1至V4，固定拟合参数后显示 |
| 地球半径R | 6.371 | 千公里，等于6371km |
| 两个站点的地心夹角 | 70 | 度，两个站点关于横轴对称 |
| 卫星距地表的最低高度h | 0.3 | 千公里，等于300km |
| 半长轴上限A | 9.3 | 千公里，第6题方案2允许申请提高此上限 |
| 要求通信的轨道段 | −20°≤θ≤20° | θ为椭圆参数角，θ＝0对应轨道最右端 |
| 最低仰角ε＝5°的概率 | 0.8 | 遮挡较少；一次任务期间该情况保持不变 |
| 最低仰角ε＝8°的概率 | 0.2 | 遮挡较多；一次任务期间该情况保持不变 |
| 能够通信时，各段单次发送成功率 | 船→卫星：0.95；卫星→岸站：0.90 | 一次完整发送要求两段都成功；随机丢包相互独立 |
| 每次任务最多发送次数 | 3 | 包含第一次发送，短时间内卫星位置近似不变 |
| 要求达到的成功概率 | 0.99 | 指定轨道段的每个位置，至少成功发送一次的概率均须达到99％ |
| α的含义 | 通信区间的参数角上限 | 要求通信的轨道段写成−α≤θ≤α，初始α＝20° |

第1、2题估计当前轨道，第3、4题评价该轨道的通信条件和发送成功概率，第5、6题计算新的设计方案。长度统一使用千公里。仰角ε从站点的当地水平面向上量起。参数角θ用于表示椭圆上的位置，α决定需要通信的区间大小；它们均不直接表示通信时长。成功概率按该区间内最不利的位置计算。
